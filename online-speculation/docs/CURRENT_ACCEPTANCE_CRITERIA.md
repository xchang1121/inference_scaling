# 当前交付与验收口径

2026-09-05 用户补充：“在线 uno 和原 uno 算法只要保持差不多的行为就已经非常不错了。”

据此，当前交付不再以“在线版本必须显著超过最强静态树”为硬门槛。
先完成本机可用的官方 Linux Uno 基线、真实在线状态更新路径，以及与原版的行为和开销对照。
性能接近原版也可以作为有价值的工程结果，仍继续争取净 TPS 改善。

保留的要求：

- target/base 与离线 adapter 隔离，在线状态不能偷偷改变 target。
- 正确的采样法则、attention/KV 不变量和明确的数值误差边界；“差不多”不被解释为允许未验证 token 直接提交。
- 在线更新确实在真实生成循环中发生，且完整开销进入 TPS；明确区分统计/策略更新和 LoRA SGD。
- 同 backend、同模型和匹配负载比较原版与在线版，报告绝对 TPS、TPF、配对差异及不确定性。
- 阶段设计与结果文档、原始记录、commit + push。

旧 R3E 和 R6A 的协议、原始数据及失败判定保持不变；不追溯修改门槛后把旧负结果宣称成功。
新实验另行冻结具体配置。用户没有指定“接近”的数值容忍区间，因此不编造一个已获认可的百分比门槛。
