# Qwen3.8-27B：IS 服务延迟与吞吐

本报告记录 Consilience 两阶段 IS 与同题 Base 的服务成本，以及历史交付、并发和 CPU 开销消融。
当前通用默认已改为 Self-Certainty；下表保留实验时的奖励与预算，配置见 [SETTINGS.md](../SETTINGS.md)。
完整池 SIR、Metropolized、Best-of-4 及 Consilience / Self-Certainty 的 100 题、12 方法准确率、论证质量与成本见[选择策略报告](QWEN38_IS_SELECTION.md)。

## 同环境的两阶段 IS 与 Base（2026-11-02）

首个固定前缀时间从搜索开始计，也不同于 HTTP 客户端 TTFT。

全部请求正常结束、思考完整，无奖励回退或总生成上限耗尽。统一重新判题时，修正了 Math-Verify 对矩阵行距

## 较长思考预算验证

同一 TP=4 环境，代码 `faaeb37`，包含增量统计数组与判题修复。固定取 skip=8 的前两题，使用 `medium`
16384 思考预算、32768 总长，其余参数不变；这两个上限只用于该组验证，不改仓库默认值。

| 题目 | Base → IS 耗时 / s | IS / Base | Base → IS 输出 token | 正确：Base → IS |
| --- | ---: | ---: | ---: | --- |
| intermediate_algebra/1197 | 185.50 → 407.44 | 2.196 | 8487 → 17120 | 是 → 是 |
| counting_and_probability/870 | 121.28 → 104.27 | 0.860 | 5566 → 3187 | 是 → 是 |
| 合计 | 306.77 → 511.70 | **1.668** | 14053 → 20307 | 2/2 → 2/2 |

估计执行量为 Base 0.764、IS 3.659 PFLOPs；最终输出 TPS 分别为 45.81、39.69。两题均进入第二阶段：
第一题直接复用保留序列（末轮 M=1），第二题末轮 M=4，最终选回保留序列。第一题的 IS 思考达到 16384 预算，
由既定策略关闭思考段后继续生成内容；未达到 32768 总生成上限，答案正确。

IS 搜索合计 481.33 s，首轮固定前缀前的等待为 458.47 s，占 95.3%；其中单请求在途合计 70.52 s，占搜索的 14.7%。
这一组的瓶颈集中在首轮完整思考，合并后续轮次无法消除该成本。两题准确率持平，时延则随选中轨迹的长度显著变化。
该组验证了最新代码的多阶段、预算关闭和复用路径；不证明增量数组带来了 1.668 倍的时延比，也不支持统一的长预算加速结论。

复现时将上节命令改为 `--questions 2 --selection-skip 8 --effort medium --max-tokens 32768`。

## 历史输出交付对照

已固定思考前缀在每轮选择后交付；无工具的最终内容在续写时增量交付。候选生成、权重与选择规则不变。
工具调用在完整解析后交付。实现见[服务说明](../../src/inference_scaling/serve/README.md)和
[`SamplingScope.finish`](../../src/inference_scaling/arllm/scope.py)。

| 交付方式 | 首段思考时间 | 首段最终内容时间 | 整题耗时 | 输出 token | 输出 TPS | 判定 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 逐轮交付思考，最终内容整段交付 | 150.70 s | 360.70 s | 360.70 s | 4378 | 12.14 | 正确 |
| 逐轮交付思考，最终内容增量交付 | 150.69 s | 310.69 s | 337.21 s | 4382 | 12.99 | 正确 |

该样本运行 4 轮 IS。原来的整段缓冲接口需等到整题完成才发送文本，因此逐轮交付思考使首段可见输出提前约
210 秒（58.2%）。这一对照来自同一请求的首次思考交付与完成时刻，未另计一次完整缓冲运行。
交付时间提前不等于生成工作量减少或 TPS 提高。

第二次运行的最终内容在该请求完成前 26.52 秒开始交付。两次的思考文本哈希不同，因此整题耗时下降
6.51% 仅为观测差异，不能归因于流式交付。两次均完整结束且判定正确，质量证据仅限这一道题。
固定种子不保证不同批处理调度下逐字一致，参见 [vLLM 复现说明](https://docs.vllm.ai/en/latest/usage/reproducibility/)。
第二次生成总量为 24457 token（搜索 23398、最终续写 1059），全部生成 TPS 为 72.53；
前向位置 32050，估计计算量 1.724 PFLOPs。第一次的服务版本未返回完整请求级成本，不作计算量对比。

随后修正了 HTTP 事件等待：任一文本增量或推理完成事件就绪即处理，消除原先最长一个保活间隔的额外等待。
该修改通过已有 CPU 测试验证；以上两行仍为修正前的记录。

使用已修正的服务，选择 `test/intermediate_algebra/1197.json` 和 `test/counting_and_probability/870.json`。
每题种子由根种子、题目 ID 和重复编号固定派生；M/K/B、奖励与长度沿用上述设置。
在同一 TP=2 服务上先并发 2 题，再串行执行，无请求预热，后执行的串行组可复用已有缓存。

| 题目并发度 | 整批耗时 | 输出 TPS | 全部生成 TPS | 估计 PFLOPs | 正确 |
| --- | ---: | ---: | ---: | ---: | ---: |

整批耗时减少 **9.5%**，全部生成吞吐增加 **8.5%**；输出吞吐增加 39.5%，但输出总量也从 4851 增至 6124 token，
因此后者包含长度变化。两组的全部生成量分别为 29891、29354 token，所有请求均完整结束且答案正确。

| 题目 | 单题耗时：串行 → 并发 | 思考 TTFT：串行 → 并发 | IS 轮数：串行 → 并发 |

## 复现与指标

设置由 [`settings/inference.json`](../../settings/inference.json) 统一提供。重测历史服务配置时按上述奖励、探索方式与引擎版本设置；
使用当前默认值得到的是新的配置对照。客户端命令：

```bash
python scripts/benchmark_is_service.py --urls http://127.0.0.1:8000 \
  --dataset math500 --questions 1 --repeats 1 --warmup 0 --concurrency 1 --cards 2 \
  --effort low --max-tokens 8192 --deadline 900 \
  --label tp2-stream --output results/tp2-stream.jsonl
```

客户端的 TTFT 包含排队和 HTTP 开销，只计非空思考或内容；角色事件、保活消息、未选候选不计入。
输出 TPS 为最终保留 token 除以整批墙钟时间；全部生成 TPS 另计未选候选和补全。
请求级成本分别记录搜索和最终续写，FLOPs 使用 `2 × 参数量 × 前向 token 数` 近似。
缺失计数、取消或抢占时不将不完整成本当作零；失败和长度耗尽纳入汇总。

## 长序列边界解析

单 token 思考标记改用原生元组查找，减少逐 token 的 Python 循环。多 token 标记仍用原有路径；
采样、奖励与思考边界定义不变，2 万组随机边界与原实现一致。
本机 CPU、同一非空思考段、每长度 15 次的中位耗时如下，仅衡量 `ThinkingParser.split`：

| 思考长度 | 原实现 / ms | 原生查找 / ms |
| --- | ---: | ---: |
| 4096 | 0.592 | 0.037 |
| 32768 | 4.740 | 0.343 |
| 131072 | 18.880 | 1.298 |

解析环节缩短约 13.8–16.0 倍；整题仍包含模型生成与其他处理，尚未测得由该修改单独产生的端到端加速。
该实现适用于任意单 token 边界，不依赖模型结构或设备算子。
