# Rollout 调度 CPU 验证

日期：2026-10-16。Python 3.14.6，NumPy 2.5.2。本次完整模拟在 CPU 上运行，约 89 秒。原始数值见 [JSON 报告](ROLLOUT_SCHEDULING_CPU.json)，实现说明见[调度说明](../methods/ROLLOUT_SCHEDULING.md)。

复现命令（仓库 Python 环境中）：

```bash
python scripts/simulate_rollout_scheduling.py --trials 500 --stationary-trials 6000 --latency-trials 64
python -m pytest tests/test_rollout_scheduler.py tests/test_streaming_vllm.py -q
```

## 输出律与目标分布

| 检查 | 规模 | 结果 |
| --- | --- | --- |
| 相同种子的完整生成对照 | `block_first` 两种设置 × 并发 1/2/8 × FIFO/fair-LPT × 500 个种子，共 6,000 组 | 全部候选、叶子、奖励、权重、选择与最终序列逐次完全相同；输出直方图 TV=0 |
| 穷举条件转移核 | 二 token、二元词表、M=K=2；4 个保留状态，每个穷举 16 组辅助采样；6 种调度 | 调度前后转移矩阵最大差 0；`max(abs(πP−π))=1.11×10⁻¹⁶`；行和误差至多 `4.44×10⁻¹⁶` |
| 从精确目标初始化后运行完整 IS | 三 token、二元词表、M=K=2，6,000 组配对抽样 | 调度前后逐次完全相同；经验分布与枚举目标的 TV≈0.00697 |
| 时延实验中的结果对照 | 两种工作负载 × 五种并发 × 64 棵树，共 640 组 | 结果全部相同，峰值并发满足配置上限 |

逐次配对检查合计 12,640 组。第一项覆盖服务时间与生成结果相关的场景。穷举检查直接运行两种算法路径，再从返回的真实权重解析积分选择概率。

这些检查验证调度保持原算法输出律，以及原条件核的目标不变性。

## 资源受限与长尾的虚拟时延

比较一轮 M=6、K=4、B=8 的完整采样树。基线为候选全部完成后才生成额外补全的 FIFO；新路径为前缀就绪即提交补全、共用同一准入实现的 fair-LPT。每个配置使用相同的 64 个种子和统计工作量。

固定长度场景每条完整序列 64 token。长尾场景按首 token 选择 EOS 概率 0.008 或 0.08，长度上限 192，产生混合长度分布。虚拟每 token 1 ms，预填充每个提示 token 0.02 ms；排序预测使用请求长度上限与已完成请求的长度历史。

| 并发上限 | 固定长度平均加速 | 长尾平均加速 | 长尾基线 P95 / s | 长尾调度后 P95 / s |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 1.000× | 1.000× | 1.07331 | 1.07331 |
| 2 | 1.000× | 1.087× | 0.56668 | 0.54229 |
| 4 | 1.159× | 1.276× | 0.40777 | 0.33964 |

本次 640 棵树的完成时间全部持平或缩短。时延收益来自消除批次屏障和更早安排依赖已满足的工作。

## 集成覆盖

资源调度测试覆盖跨题公平、KV 水位、预填充预算、老化、尾部保护和异常清理。

集成测试覆盖思考边界跨事件、原生空思考标记续写、提前 EOS、保留叶子奖励复用、流式前缀统计量复用、多个调用者的共享上限、逻辑请求同名隔离、评分使用同一引擎、生成/评分异常清理，以及服务默认的逻辑停止。异步 vLLM 适配使用 CPU 假引擎覆盖 DELTA 事件和持久请求生命周期。

本环境全量回归：315 通过、2 跳过、1 个失败。失败为 `test_growing_cache_matches_the_dynamic_cache_through_crops_and_row_selection`：Transformers 5.20 拒绝测试中的 `DynamicCache.crop(4)`。两项跳过的原因是 `math_verify` 依赖缺失。Ruff 全库检查通过，新增调度核心模块的定向类型检查通过。
