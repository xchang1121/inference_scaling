# 更智能的检索触发与资料插入：方案调研

检索日期：2026-11-09。以下区分论文原方法、当前实现条件和针对本项目的设计建议。只查阅论文、作者项目和官方源码；未运行这些方法的新模型实验，也未改变本轮 336 条冻结对照。

## 可以直接借鉴什么

| 方案 | 何时、用什么检索 | 如何继续生成 | 对当前管线的意义 |
|---|---|---|---|
| [FLARE，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.495/) | 预览下一句，低置信 token 提示知识缺口，以将要生成的内容构造查询 | 取得资料后重新生成该句 | 无需训练；比固定 32 token 更接近具体事实需求，但需要草稿和回退，不只是追加资料 |
| [DRAGIN，ACL 2024](https://aclanthology.org/2024.acl-long.702/) | 将词分布熵、后续 attention 影响和非停用词语义筛选组合；从上下文 attention 选查询词 | 在检测到的知识缺口处截断，结合资料继续生成 | 无需训练；同时改进触发和查询。当前后端没有导出所需 attention，接入成本较高 |
| [IRCoT，ACL 2023](https://aclanthology.org/2023.acl-long.557/) | 将推理句与检索交替，已推导的中间信息参与下一跳检索 | 按推理步骤更新资料、继续求解 | 适合作为句界与查询更新基线；原方法不等于已经学会“只有必要时才查” |
| [Search-o1，EMNLP 2025](https://aclanthology.org/2025.emnlp-main.276/) | 主模型主动输出搜索请求 | 独立的 Reason-in-Documents 生成过程提炼资料，再返回主轨迹 | 同时处理“如何插入”；需要模型遵守搜索协议，且额外资料分析也有生成成本 |
| [Self-RAG，ICLR 2024](https://arxiv.org/abs/2310.11511) | 学习检索、相关性、支持性等反思 token | 用反思信号控制检索和候选生成 | 需要相应训练或专用 checkpoint；给当前冻结模型加几个标签不能称为复现 |
| [Search-R1，COLM 2025](https://arxiv.org/abs/2503.09516) / [R1-Searcher，2025](https://arxiv.org/abs/2503.05592) | 用 RL 学会多轮搜索及查询生成 | 将检索环境接入推理轨迹 | 适合长期学习策略；需要训练或更换 checkpoint，并非当前控制器的即插即用触发器 |
| [Sufficient Context，ICLR 2025](https://arxiv.org/abs/2411.06037) | 判断问题与现有上下文是否足以构造答案，不依赖 gold 答案 | 原论文用于分析及选择性回答 | 可借用为外部“证据缺口”信号；改造成在线检索触发器属于本项目的新设计 |
| [DTR，arXiv 2026](https://arxiv.org/abs/2601.03908) | 用初步回答的平均负 log probability 决定是否检索，再结合原问题和生成上下文走两路检索 | 筛选联合相关的证据后回答 | 无需训练，适合查询级是否检索基线；原方法不是逐思考步骤的插入位置策略 |

作者实现也支持上述区分：[FLARE 源码](https://github.com/jzbjyb/FLARE)、[DRAGIN 源码](https://github.com/oneal2000/DRAGIN/blob/main/src/generate.py)、[Search-o1 源码](https://github.com/RUC-NLPIR/Search-o1)。DRAGIN 当前实现显式调用 `output_attentions=True`，并包含额外的 attention 前向；不能把所需信息当作现有 SC 指标自动附带。此次读到的 `src/generate.py` Git blob 为 `b56d2825503ea1d88ce32fa55e25604a2fd7d6be`。

当前 SC 使用 $D_{KL}(U\Vert p)$，DRAGIN 的不确定性项使用 $H(p)$；不能从一个已保存的 SC 标量反推出完整词分布的熵。接入原方法还需要提供相应的熵统计，不能只把现有 SC 改一个名字。

另一类 [Adaptive-RAG，NAACL 2024](https://aclanthology.org/2024.naacl-long.389/) 用较小分类器，按问题复杂度选择不检索、单次或多次检索。它解决入口路由，不能直接替代轨迹中途的触发和插入边界。

## 对本项目的建议

优先评估 **FLARE 式待确认草稿 + 外部证据缺口检查 + 小段证据回填**。这是基于上述工作和当前管线的组合建议，不是任一论文方法的原样复现，也没有本项目上的质量提升结论。

1. 在完整推理步骤边界形成一个待确认的下一步或事实主张。草稿先不提交为最终前缀；低置信的实体、版本、数值、参数名可以成为检查候选，SC 变化作为辅助信号。
2. 外部控制器检查当前资料能否支持该主张，返回缺失事实及查询。这样不要求主模型自己发工具调用。该检查器可能犯错，需要独立评估，不能当作事实 oracle。
3. 查询围绕缺失的关系或属性组织，保留产品、版本、错误码等约束。既可按原问题检索，也可按当前子问题检索；对伪上下文引入错误线索的风险进行对照。
4. 只回填与缺口对应的短证据，保留来源和适用条件。先定位答案所在段落，再决定给模型哪些 token；整篇文档只取开头的策略可能根本没暴露所需参数。段落检索和重排仍须实测，不能假定切块必然提升召回。
5. 在已保存的步骤边界重建输入，再生成待确认内容。显式资料区或模型支持的工具消息边界可以作为候选格式；任何一种都必须验证自然 `</think>`、thinking 内 EOS、空答案和正确性，不能先假定它保持推理连续。

仅改进触发不足以解决注入后的终止行为。当前预算/格式对照中已经观察到：相同长度的无关正文也能导致立即关闭 thinking；外层文案换成等长换行后，又可能在 thinking 内直接 EOS。[本轮冻结方案](ONLINE_INJECTION_FOLLOWUP_PROTOCOL.md)约定逐条保留这些结束类型与完整轨迹。

## 怎样区分收益来自哪里

先修复并验证输入边界，再做相同资料预算下的配对：静态 RAG、统一步骤边界的固定触发、FLARE 式触发、证据缺口触发、二者组合。保留相同长度无关正文及无注入条件。随后单独比较原问题查询与缺失事实查询，避免同时改变位置、查询和证据长度后归因不清。

除回答质量、空答案、结束类型和触发覆盖率外，还应记录无必要检索率、查到的片段能否填补缺口，以及检索后的质量变化。所有草稿、检查器、查询改写、资料提炼和被丢弃的生成都计入耗时与计算成本。

阈值与检查器在独立开发集上校准，不在当前反复查看的八道题上选最优值。对所有条件统一草稿切分、回退和种子规则；原同种子缓存续写测试仍有分歧，使用缓存分叉前应完成相应一致性验证，或报告重算前缀的实际成本。

当前 336 条对照保持冻结。这份调研不构成已执行的新策略实验。
