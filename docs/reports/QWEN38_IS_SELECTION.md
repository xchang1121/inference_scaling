# Qwen3.8-27B：100 题的选择策略与奖励对照

## 设置与比较对象

评估补全数量、候选池选择方式及模型内在奖励对答案正确率、论证质量和推理成本的影响。
固定 **100 题、12 种方法、1200 次测量**，每题每种方法运行一次；所有表格均按完整 100 题汇总。

- 模型：Qwen3.8-27B BF16，权重版本 `1d4bf0f2ff60`；Ascend 910B3、TP=2。
- 数据：MATH-500，版本 `6e4ed1a2a79a`，五级题，选择种子 20260911；沿用设置中的 8 题排除清单。
  分层顺序前 20 题用于开发，评测取 `[20,120)`，题目在生成前固定。
- 采样：根种子 20260808，温度 1、完整词表、默认 8 词惩罚强度 1；方法顺序逐题轮换。
- 长度：`low` 4096 思考预算、8192 总生成上限、262144 上下文。思考预算耗尽后关闭思考段，继续生成最终内容。
  各方法统一逐序列长度上限，总 token 与 FLOPs 按实际执行统计。
- IS：思考段内两阶段探索，首轮 M=4、B=1024、K=1 或 2；末轮为自适应 M、K=1，复用保留序列。
  在 B 以内结束的候选仅有一条补全。各方法未强制共享同一候选池。

C 表示 Consilience，SC 表示 Self-Certainty。标准答案仅供生成后的正确性统计，不参与候选选择。

| 方法 | 选择方式与奖励 |
| --- | --- |
| Base | 一次普通思考采样 |
| 快速 IS + C，K=1 | 按前缀估计提前选择并取消剩余请求，`selection_ready=true` |
| 完整池 SIR + C，K=1 / 2 | 等完整奖励到达后按归一化权重重采样 |
| 逐条 Metropolized + C，K=1 / 2 | 在完整补全之间逐条更新选择索引 |
| 按块 Metropolized + C，K=2 | 先更新候选块索引，再按权重选块内补全 |
| Best-of-4 + C | 生成四份完整思考及最终内容，选择思考段奖励最高的一份 |
| 快速 IS + SC，K=1 | 沿用快速 IS，仅替换奖励 |
| 逐条 Metropolized + SC，K=1 / 2 | 沿用相同 K 的逐条选择核，替换奖励 |
| 按块 Metropolized + SC，K=2 | 沿用按块选择核，替换奖励 |

完整池方法均关闭提前选择；Metropolized 指 IS 候选池内的选择核，非完整序列后缀 MH。
同核、同 K 的 C / SC 对照考察奖励变化；完整池与快速 IS 的比较同时改变等待方式和选择核。
实现见[完整候选池选择](../methods/ALGORITHMS.md#is-metropolized)。

Consilience 使用思考段 top-5 概率统计，奖励温度 2、首段惩罚 3、首尾窗口比例 0.2、跳过开头比例 0.05。
Self-Certainty 使用**全词表 KL(U‖p) 的思考段均值**，U 为词表上的均匀分布，奖励温度 0.25、评分温度 1。
p 包含同一词表惩罚及温度处理。定义与实现见[模型奖励](../methods/ALGORITHMS.md#alg-self-certainty)。

### 执行与计量

两台服务器各承担 50 题，同一道题的所有方法在同一 TP=2 实例配对。
不同方法分次运行，共享负载可能影响墙钟。源版本、公共生成设置、种子、输出哈希及退出状态均已核对。

两实例共用 vLLM `0fc695fc6d1d`、vllm-ascend `5cb98caaadef` 及已有兼容修正；
Transformers 分别为 5.5.4 / 5.14.1，torch-npu 2.10.0.post4、CANN 9.1、驱动 26.1.1。
异步执行、前缀缓存、分块预填充和 `FULL_DECODE_ONLY` 执行图开启；每次测量前清空前缀缓存。

SC 通过 `scalar_self_certainty` 在设备端计算全词表 KL 标量，随生成返回，额外模型评分前向为 0。
Best-of-4 的运行也开启了该统计开关；词表归约与传输耗时计入墙钟。
Best-of-4 为四条候选都生成最终内容，IS 仅对选定思考生成一份最终内容，成本分别计入。

计时包含搜索与最终内容生成，排除模型加载、64-token 预热、清缓存、最终输出判题及写盘。
Best-of-4 的入口还在计时内对四候选进行 CPU 判题，判题结果不参与选择；该开销保留。
FLOPs 采用 `2 × 26,895,998,464 × 实际执行 token 位置数` 的稠密近似，包含预填充、执行图填充及取消前已执行的工作；
词表归约等非模型前向成本仅反映在墙钟中。

## 答案正确率

全部 1200 条测量正常完成，CPU 重判与原始判分一致。箭头左侧为 Math-Verify 0.9 原判，右侧为完整最终答案复核结果。
正确率区间为 Wilson 95% 区间；胜 / 负表示该方法正确而 Base 错误 / 该方法错误而 Base 正确。

所有方法相对 Base 的准确率差区间均包含 0，双侧精确 McNemar 检验均 p≥0.4531。
部分方法零次负例使 bootstrap 下界为 0，仍不足以建立优势或非劣保证。

复核纠正了 15 条假阴性：角度单位或答案定位 6 条、参数不等式与区间等价 8 条、实根集合表达 1 条；
另纠正 1 条假阳性。后者来自按块 SC 的 `counting_and_probability/731`：
最终分段答案在 k<1 时写成 1/(2k²)，正确概率对所有 k>0 都是 1/2；自动判题只匹配到正确分支。
原输出、原判和修正分别保留，答案修正不改变论证质量等级。

`precalculus/768` 未指定反余切分支：参考解取两正根，十二种方法均按值域 (0,π) 给出四根。
主统计保留参考答案口径；接受输出声明的分支时，所有方法各增加 1 题，配对差异不变。这项敏感性单列。

## 最终内容的论证质量

隐藏方法、分数、耗时与自动判分后，按最终展示的推导审核，每份输出保存具体数学依据。
等级为：**成立**——主要推导有效；**局部错误**——可局部修正的算术、符号或遗漏；
**关键错误**——决定性推导无效、必要前提无依据或矛盾未解决。

每种方法汇总 100 份输出，采用最近一次完整审核。† 标记的方法来自基础对照审核，其余七种来自同一次奖励与选择核对照审核；
论证质量的配对比较限于同一审核组，跨组不作统一排名。审核由助手完成，未经独立人工复核，亦未全面审核内部思考。

相对同核 C，逐条 SC K=1、K=2、按块 SC K=2 的成立数分别增加 3、2、8 题；

部分输出直接假设函数为二次多项式，结论正确但唯一性依据缺失；Best-of-4 通过加性函数在整数点的性质补齐了证明。
模型内在奖励仍可能选中答案正确但关键论证不成立的输出。

## 结论

按块 Metropolized + SC K=2 为 95/100，Base 为 92/100，快速 SC IS 与 Best-of-4 均为 94/100。
按块 SC 相对快速 SC 净多对 1 题，代价为约 20% 更多耗时和 75% 更多 FLOPs，准确率差区间仍包含 0；
逐条 SC K=1 / K=2 也未取得更好的质量与成本组合。

推理扩展方法中，快速 SC 的平均时延较低；Best-of-4 的累计 FLOPs 和 P95 更低。
据此将思考段 Self-Certainty、两阶段探索、SIR 提前选择和首轮 M=4/K=1/B=1024 设为通用默认；
完整池选择核保留为显式选项。CLI、服务与默认性能评测共用该配置，不按数据集切换。
通用思考档位与长度预算保持原配置，不沿用本实验的短输出上限；本次结果不构成其他任务或长度上的优势保证。
本实验统一逐序列长度设置，未配平总 token / FLOPs，不能据此判断固定总计算预算下的优劣。

## 复现

使用[统一评测入口](../../scripts/benchmark_is_gpu.py)与共享设置，按上述模型、数据、奖励和采样参数配置。
硬件设置为 `ar.engine.device="npu"`、TP=2、异步执行、单题 worker=1；
`engine_kwargs` 中启用 `compilation_config={"cudagraph_mode":"FULL_DECODE_ONLY"}`。
基础算法设置为 M=4、K=1、B=1024、`two_stage`、SIR、`selection_ready=true`，入口按方法覆盖相应字段。

以下命令均展示完整 100 题范围。原始测量的逐题实例分配保存在结果记录中；复现墙钟比较时应保持实例分配和运行负载一致。

```bash
VLLM_USE_V2_MODEL_RUNNER=0 python scripts/benchmark_is_gpu.py --settings settings/inference.json \
  --study selection --dataset math500 --questions 100 --selection-skip 20 --repeats 1 \
  --effort low --max-tokens 8192 --label selection --output results/selection.jsonl
```

奖励对照开启 `ar.engine.vllm.scalar_self_certainty=true`；SC 的 scope 为 thinking、temperature 为 0.25、
score_temperature 为 1。以下两个入口分别运行 Best-of-4 / 快速 SC，以及三个完整池 SC 模式：

```bash
VLLM_USE_V2_MODEL_RUNNER=0 python scripts/benchmark_is_gpu.py --settings settings/inference.json \
  --study rewards --modes bon-consilience is-self-certainty --dataset math500 \
  --questions 100 --selection-skip 20 --repeats 1 --effort low --max-tokens 8192 \
  --label rewards --output results/rewards.jsonl

VLLM_USE_V2_MODEL_RUNNER=0 python scripts/benchmark_is_gpu.py --settings settings/inference.json \
  --study selection-self-certainty \
  --modes met-k1-self-certainty met-k2-self-certainty block-met-k2-self-certainty \
  --dataset math500 --questions 100 --selection-skip 20 --repeats 1 --effort low --max-tokens 8192 \
  --label selection-sc --output results/selection-sc.jsonl
```
