# Qwen3.8-27B：100 题的选择策略与奖励对照

## 设置与比较对象

评估增加补全数量、改变候选池选择方式及模型内在奖励，对最终答案、论证质量和推理成本的影响。
固定原 30 题及新增 70 题，每题每种方法运行一次，共 **100 题、12 种方法、1200 次测量**。
本轮加入三种 Metropolized + Self-Certainty，原九方法的 900 条测量直接复用，未重新生成或调整参数。

- 模型：Qwen3.8-27B BF16，权重版本 `1d4bf0f2ff60`；Ascend 910B3、TP=2。
- 数据：MATH-500，版本 `6e4ed1a2a79a`，五级题，选择种子 20260911；沿用设置中的 8 题排除清单。
  分层顺序前 20 题用于开发；原 30 题取 `[20,50)`，新增 70 题取 `[50,120)`，生成前固定，互不重叠。
- 采样：根种子 20260808，温度 1、完整词表、默认 8 词惩罚强度 1；方法顺序逐题轮换。
- 长度：`low` 4096 思考预算、8192 总生成上限、262144 上下文。思考预算耗尽后关闭思考段，继续生成最终内容。
  各方法统一逐序列长度上限，总 token 与 FLOPs 按实际执行统计。
- IS：思考段内两阶段探索，首轮 M=4、B=1024、K=1 或 2；末轮为自适应 M、K=1，复用保留序列。
  在 B 以内结束的候选仅有一条补全。各方法的随机请求不同，未强制共享同一候选池。

| 方法 | 选择方式与奖励 |
| --- | --- |
| Base | 一次普通思考采样 |
| 快速 IS，K=1 | Consilience；`selection_ready=true`，按前缀估计提前选择并取消剩余请求 |
| 完整池 SIR，K=1 / 2 | Consilience；等完整奖励到达后按归一化权重重采样 |
| 逐条 Metropolized，K=1 / 2 | Consilience；在完整补全之间逐条更新选择索引 |
| 按块 Metropolized，K=2 | Consilience；先更新候选块索引，再按权重选块内补全 |
| Best-of-4 + Consilience | 生成四份完整思考及最终内容，选择思考段奖励最高的一份 |
| 快速 IS + Self-Certainty | 沿用快速 IS、K=1，仅替换奖励 |
| 逐条 Metropolized + Self-Certainty，K=1 / 2 | 沿用相同 K 的逐条选择核，替换奖励 |
| 按块 Metropolized + Self-Certainty，K=2 | 沿用按块选择核，替换奖励 |

完整池方法均关闭提前选择；Metropolized 指 IS 候选池内的选择核，非另一次完整序列后缀 MH。
实现见[完整候选池选择](../methods/ALGORITHMS.md#is-metropolized)。
下文 C 表示 Consilience，SC 表示 Self-Certainty；未注明奖励的原七方法使用 Consilience（Base 无奖励）。
新补测优先与同核、同 K 的 C 比较；与快速 SC IS 的比较同时改变完整池等待和选择核。

Consilience 使用思考段 top-5 概率统计，奖励温度 2、首段惩罚 3、首尾窗口比例 0.2、跳过开头比例 0.05。
Self-Certainty 使用 **全词表 KL(U‖p) 的思考段均值**，U 为词表上的均匀分布，奖励温度 0.25、评分温度 1。
p 包含同一词表惩罚及温度处理；完整词表均参与计算。定义与实现见[模型奖励](../methods/ALGORITHMS.md#alg-self-certainty)。
标准答案只供正确性统计，候选选择使用上述模型奖励。

### 执行与计量

两台服务器各承担原 15 题及新增 35 题；同一道题的所有方法始终在同一 TP=2 实例运行。
原七方法使用代码 `39dfa0a`；Best-of-4 与快速 SC IS 使用 `150b1ba`；三个 Metropolized + SC 使用 `6bde29b`。
三批使用同题、同种子、同实例和公共生成设置；源版本、配置、输出哈希及退出状态均已核对。
各批独立运行，共享服务器的负载变化仍可能影响耗时。

两实例共用 vLLM `0fc695fc6d1d`、vllm-ascend `5cb98caaadef` 及已有兼容修正；
Transformers 分别为 5.5.4 / 5.14.1，torch-npu 2.10.0.post4、CANN 9.1、驱动 26.1.1。
异步执行、前缀缓存、分块预填充和 `FULL_DECODE_ONLY` 执行图开启；每次测量前清空前缀缓存。

补测开启 `scalar_self_certainty`：设备端从全词表 log-probability 计算一个 KL 标量，随生成返回，
保留原生异步调度，额外模型评分前向为 0。该开关也给补测中的 Consilience 请求增加一次词表均值归约；
归约和传输耗时计入墙钟。Best-of-4 生成四份最终内容，IS 仅对选定思考生成一份最终内容，成本分别计入。

计时包含搜索与最终内容生成，排除模型加载、64-token 预热、清缓存、最终输出判题及写盘。
Best-of-4 的现有入口还在计时内对四候选进行 CPU 判题，判题结果不参与选择；该开销保留在本次墙钟中。
FLOPs 采用 `2 × 26,895,998,464 × 实际执行 token 位置数` 的稠密近似，包含预填充、执行图填充及取消前已执行的工作；
词表统计归约等非模型前向成本仅反映在墙钟中。

取消前执行量已计入 FLOPs。Self-Certainty IS 有 40 题进入第二阶段、7 题选中思考达到预算边界。
三种 SC 补测分别有 39 / 38 / 36 题进入第二阶段，12 / 12 / 8 题选中思考达到预算边界；
没有总长耗尽、取消、回退或抢占，额外模型评分前向均为 0。

## 结论与复现

全样本的答案准确率为 Base 92%、快速 C IS 93%、快速 SC IS 94%、按块 SC K=2 95%；
最高值比 Base 净多对 3 题，配对区间仍包含 0。按块 SC 的论证审核有积极变化，但相对快速 SC 的
净准确率收益仅 1 题，新增 70 题持平，代价为约 20% 更多耗时和 75% 更多 FLOPs。
逐条 SC K=1 / K=2 相对快速 SC 也未取得更好的质量与成本组合。

在本批推理扩展方法中，快速 SC 的平均时延较低；Best-of-4 同为 94/100，累计 FLOPs 和 P95 更低，
但两者之间也没有稳定准确率或平均时延优势的证据。完整池选择核继续保留为显式选项，默认奖励、选择核与预算不变。
本次比较对应相同逐序列长度设置；固定总 token / FLOPs 下的质量结论超出本次测量范围。
