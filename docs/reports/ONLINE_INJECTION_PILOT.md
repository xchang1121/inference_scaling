# 技术文档在线知识注入：首轮结果

后续已完成[去除 effort 提示、三档思考预算与同长度内容/格式对照](ONLINE_INJECTION_ABLATION.md)，另有[智能检索触发方案调研](ADAPTIVE_RETRIEVAL_OPTIONS.md)。本页保留首轮配置和原始结论，第二轮用于复核停止行为的解释。

分支 `codex/online-knowledge-injection-20261109` 实现了外部控制器自动检索、按原始 token 前缀追加资料和继续生成，模型不需要输出工具调用。覆盖 BM25、字符 TF-IDF、RRF，固定位置、低概率、SC 下降、文本规则及组合触发，以及静态、起点、推理中、句界和回答前的位置对照。

所有正式测量统一在 `27.106.124.198` 的物理 3 号单卡运行，TP=1，Qwen3.8-27B 冻结 revision、BF16、温度 1。24 题各运行 13 种方法，共 312 份最终回答；生成均正常结束，没有失败重试。生成源码冻结在 `cbf7998dfcf997436137a0e7385de2da63f5f031`，生成、推理与证据预算分别为 512、256 和 1,024 token。

TechQA 的固定 32-token BM25 相对闭卷提高 9.41 个百分点，题级 95% 配对 bootstrap 区间为 [+3.84, +15.05]。耗时为闭卷 0.666 倍，原生图计算量估算为 1.744 倍：它串行生成更短，但资料 prefill 与重算使计算量增加。静态 RAG 的 F1 相近，成本为 2.403 倍。不能据此宣布某种检索器或注入位置普遍最优。

## 解释结果时需要保留的限制

- TechQA 仅抽取 NVIDIA 版原始 DEV 中 8 道可回答题，索引使用全部 28,481 份文档；评分为生成回答 F1/EM，不能与 IBM 原抽取式官方成绩直接比较。全部 104 份回答另有来源复核，但不是独立盲审，也没有替代预定指标。
- 起点与三个固定 32-token 方法在 TechQA 注入后都立即由模型关闭推理，资料后推理 token 为 0。这能说明资料改变了后续回答，尚不能证明改善了资料后的推理过程。
- 官方规则题是八份文档改述派生的人工诊断。闭卷有 8/16 份答案可提取 JSON，起点注入有 15/16 份，因此严格得分受格式和预算影响。Redis 的一个秒数字段存在歧义；模型正确描述 60 秒 TTL 的输出仍被冻结 gold 的客户端等待秒数 0 扣分。所有题目、gold 和主评分保留，另提供事后敏感性分析。
- 回答前注入在 TechQA 有 3/8 份空回答，在官方规则题有 14/16 份空回答；没有重试择优。其较低耗时不能解释为完成相同任务的加速。
- 命中文档 ID 不等于已暴露答案片段。Q011 的核心 `-J-Xmx` 位于长文档后部，所有实际注入片段都未包含该参数；Q209 则存在 gold ID 之外的正确替代资料。一次额外 CPU 切块诊断的 Hit@2 从 3/8 降至 2/8，负结果也保留。
- 句界等待采用单 token 请求，改变了后续请求种子和随机流。题级 bootstrap 没有进行多重比较校正，官方规则题同文档两问的相关性也未单独建模。

## 缓存验证与可复现材料

小型真实因果模型的 CPU 追加与兄弟分支测试通过。目标模型的预定同种子缓存续写测试中，一支只输出 EOS 并与重算一致，另一支从第二个 token 开始出现不同采样路径；原测试记为失败。两支缓存运行都实际复用 1,536 个前缀 token，重算运行命中为零。采样序列差异尚不能区分随机流变化与模型状态问题，当前不构成完整缓存分支一致性的证明。

事后固定历史诊断沿用同一父前缀和两份资料，在原记录的八 token 历史上逐位置预测一个贪心 token：16/16 个位置的 token 与 log probability 相同，缓存各复用 1,536 token，重算均命中为零。它支持所测固定条件下的状态复用，但没有比较全部词表分布，也未定位原随机续写分歧的根因；原测试仍记为失败。补充诊断的零测量初始化接口错误也已保存。

验证直接导入正式冻结源码。Git LF 与冻结包 CRLF 的字节差异单独核对，归一化后 75 个核心文件内容一致。原预检查、修订协议、执行脚本、失败记录和运行时源码哈希都保留。
