# IRCoT / ThinkRetrieve 正式实验结果

同一组 16 道 TechQA DEV 题 × 2 个随机种子 × 11 个实验组，共 352 项完整原生测量。IS 算法、Self-Certainty 奖励及参数保持不变；本次只改变检索和注入控制器。

本次结果支持检索到的事实内容有用：IRCoT 和静态事实注入均优于各自等长噪声。IRCoT 的平均 F1 最高，但相对静态事实注入的增益区间跨零，尚不能据此确认动态检索稳定更好。静态事实注入在本次测量中耗时更少，可作为后续扩样的成本基线。

ThinkRetrieve 在当前模型与 TechQA 适配下没有带来收益，平均 F1 低于无注入 IS 和静态样例注入，且耗时更长。真实样例组有 13/32 个空答案，噪声组有 20/32 个；终止位置分别为控制器思考阶段 9/11 个、IS 选中思考轨迹 4/9 个。这定位了失败阶段，但不能单独证明模板、检索内容或奖励造成了 EOS。逐例信息见 [空答案诊断](../../diagnostics/EMPTY_ANSWERS.md)。

总生成 token 包括检索代理、临时答案、探测、所有被丢弃的 IS 候选及最终答案。注入文本属于输入，单独记录。所有 IS 组共享 65,536 token 的搜索与控制器总预算，保留思考上限为 8,192 token；普通直接生成是单条思考轨迹，上限同为 8,192 token，不执行候选搜索。每组最终答案上限均为 16,384 token。实际消耗并不强行相等，直接生成用于提供成本与延迟基准。耗时包含完整检索与生成流水线；每组开始前清空 prefix cache，模型加载、一次性索引构建和预热不计入该均值。

## 主要配对比较

- 无注入 IS − 普通直接生成：-0.157 F1 点，95% 区间 [-0.819, +0.452]。
- IRCoT + IS − 无注入 IS：+7.239 F1 点，95% 区间 [+3.653, +11.188]。
- IRCoT + IS − 静态事实 + IS：+2.002 F1 点，95% 区间 [-0.072, +4.289]。
- ThinkRetrieve + IS − 无注入 IS：-2.304 F1 点，95% 区间 [-4.133, -0.530]。
- ThinkRetrieve + IS − 静态完整样例 + IS：-3.230 F1 点，95% 区间 [-4.857, -1.700]。
- ThinkRetrieve + IS − 仅重新思考 + IS：-1.847 F1 点，95% 区间 [-3.667, +0.070]。

## 内容是否比等长无关文本有用

- 静态事实 + IS − 静态事实等长噪声：+5.412 F1 点，95% 区间 [+2.202, +9.524]。
- IRCoT + IS − IRCoT 等长噪声：+7.556 F1 点，95% 区间 [+3.702, +11.931]。
- 静态完整样例 + IS − 静态样例等长噪声：+1.132 F1 点，95% 区间 [+0.268, +2.226]。
- ThinkRetrieve + IS − ThinkRetrieve 等长噪声：+2.761 F1 点，95% 区间 [-0.153, +5.845]。

实际注入长度完全匹配 117/128 对。ThinkRetrieve 噪声组使用自己的思考轨迹和临时查询，以参考组相同注入次序的长度替换整个样例内容；如果真实 EOS 提前终止，缺失的后续注入保留为不匹配记录，不补造生成。IRCoT 噪声组复跑同一相关检索代理，只替换独立 reader 接收的事实内容。11 对不匹配全部来自 ThinkRetrieve 噪声组在第二次注入前 EOS，已发生的注入包仍逐个精确等长。因此 ThinkRetrieve 的 32 对中只有 21 对总注入长度相同；其总体对比不能视为严格等长的内容消融，也不应删除早停样本后再解释为无偏的内容效果。其余三类对照各 32/32 对精确匹配。

## 协议适配与边界

IRCoT 使用 BM25 的问题检索及最多两轮“生成下一句—检索”，随后由全新 IS reader 读取累计事实。ThinkRetrieve 保留思考前缀，在自然思考结束或每 2,048 token 处生成临时答案，以 E5-base-v2 的问题与答案联合向量检索完整 TRAIN 操作样例，最多插入两次，再交给相同 IS。它们的比较覆盖整套适配流水线，不能解释为只改变插入位置的纯因果效应。

正式版使用 ThinkRetrieve 官方模板及样例格式。初版改写模板在两道 TRAIN 冒烟题上出现早停；独立冷缓存诊断复现该现象，官方模板在其中一道题上恢复正常继续生成，因此在正式运行前恢复原模板。旧版 22 项结果、六次诊断以及全部源码已保留，随后完整重跑 22 项 TRAIN 冒烟。没有按当前 DEV 输出或 TRAIN F1 调整模板，也没有屏蔽 EOS。

这是一组已在前序实验使用过的小规模 DEV 题，结论属于该设置下的探索性机制结果，并非论文基准复现，也不代表未见测试集上的普遍收益。置信区间按题聚类：先平均两个种子，再做 5,000 次题级 bootstrap；没有做多重比较校正。区间跨零时不据此宣称稳定提升。

## 审计与复核

全部 34,518 项离线审计通过；最终截断 0 项。审计重算生成成本、前缀拼接、Self-Certainty 奖励、IS 候选权重与抽样选择，并核对冻结文件哈希、题目与种子集合、噪声内容及长度。

正式测量累计生成 851,363 token，流水线累计 8.755 小时；含启动和退出的原生任务占用 8.877 设备小时。

逐项答案与成本见 [answers.jsonl](answers.jsonl)，完整配对区间和额外诊断见 [REPORT.md](REPORT.md)，审计明细见 [audit.json](audit.json)。发布包提供原始 token 轨迹、冻结源码和无需模型的离线复算脚本。
