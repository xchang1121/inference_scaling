# 动态检索 + inference scaling：完整实验结果

本轮改进了旧动态方案，但没有证明“中途插入”优于静态 RAG，也没有证明答案验证器带来稳定的额外质量收益。12 道新题、每题两个种子上，动态短证据 + 验证式 IS 的词汇 F1 为 **14.069**，旧动态方案为 **11.199**；同配置静态验证式 IS 为 **14.713**，静态短证据 + SC 为 **14.750**。这里的 F1 衡量参考答案的词汇重合，不等于事实正确率。

20 题 × 2 种子 × 8 方法共 **320 个原生逻辑条件**全部完成。12 道新题用于主分析，8 道旧题仅作回归诊断；共享检索前缀不算额外独立试验。每题先平均两个种子，再做题级配对 bootstrap。所有区间都是小样本、未做多重比较校正的描述性 95% 区间。

SC 在这里表示 self-certainty 候选评分。检索触发使用对应版本的 FLARE/gap 或问题锚定缺口检查；IS 选择沿用完整候选池的 block-Metropolized 索引更新。答案验证是未经额外训练的推理时适配，不是训练版 Self-RAG 或论文方法的完整复现。

## 新题上的质量与实际成本

下表为每条件均值。PFLOPs 是根据原生执行图形状计算的 dense/padded 估算，秒数是对应执行单元耗时；两者都不能用生成 token 数直接替代。

| 方法 | F1（0–100） | 总生成 token | 图估算 PFLOPs | 秒 |
|---|---:|---:|---:|---:|
| 旧静态窗口 + block-Met SC | 13.385 | 4,407.4 | 1.591 | 97.22 |
| 旧动态 FLARE/gap + block-Met SC | 11.199 | 5,011.9 | 1.586 | 119.88 |
| 静态问题锚定短证据 + SC | **14.750** | **2,787.6** | 1.385 | **83.68** |
| 动态问题锚定短证据 + SC | 13.729 | 3,245.9 | 1.475 | 98.65 |
| 静态短证据 + 验证式 IS | 14.713 | 4,807.8 | **1.149** | 97.31 |
| 动态短证据 + 验证式 IS | 14.069 | 5,330.0 | 1.224 | 112.00 |
| 静态同长度无关正文 + 验证式 IS | 11.015 | 5,998.6 | 1.334 | 117.02 |
| 动态同长度无关正文 + 验证式 IS | 11.615 | 6,103.8 | 1.330 | 124.73 |

主要配对差值，单位为 F1 百分点：

- 动态验证式 IS − 旧动态：**+2.871 [0.735, 5.760]**。
- 动态短证据 + SC − 旧动态：**+2.530 [0.214, 5.452]**。不用答案验证器也取得了主要的均值提升；这一比较同时改变检索和搜索配置，不能全归因于其中一个组件。
- 动态验证式 IS − 动态短证据 + SC：**+0.341 [−0.792, 1.405]**，没有清楚的额外质量收益。
- 动态验证式 IS − 静态验证式 IS：**−0.643 [−1.618, 0.215]**，没有动态优于静态的证据。
- 动态验证式 IS − 旧静态：**+0.684 [−4.304, 4.976]**，同样不能确认胜出。
- 动态真实证据 − 动态无关正文：**+2.455 [0.277, 5.404]**；静态真实证据 − 静态无关正文：**+3.698 [0.976, 7.401]**。本轮结果支持正文内容有作用，不能只用插入格式解释改善。

相对旧动态方案，新动态验证式 IS 多生成 6.35% token，图估算计算量减少 22.83%，耗时减少 6.58%。相对新动态 SC，它多生成 64.21% token、耗时增加 13.54%，但图估算计算量减少 17.01%；不同成本指标给出不同取舍，不能只报其中最有利的一项。相对静态验证式 IS，动态版多生成 10.86% token、增加 6.49% 图估算计算量、增加 15.09% 耗时，F1 均值反而较低。

完整数值与预先列出的对照见 [REPORT.md](REPORT.md)，图见 [grounded-retrieval-is.png](figures/grounded-retrieval-is.png)。所有 320 个条件的 normalized EM 均为 0；长技术答案上的 EM 本身很苛刻。

## 动态步骤实际发生了什么

新题的 24 个题目/种子组合中，静态提取器接受了 18 个证据包，动态接受了 14 个。动态 14 次成功插入**全部回退已有思考到偏移 0**；旧题的 14 次成功动态插入也全部如此。本轮没有得到“保留已完成的有效推理，再补入证据”的成功样本。

新题中有 10/24 对静态与动态条件最终使用完全相同的非空证据和搜索输入。验证式 IS 的返回答案有 8/24 对逐 token 相同。动态版在这些情况多付出了探测成本，因此不能把所有改进解释成插入时机的收益。全部新题平均，动态验证式 IS 比静态版多生成 522.1 token，多用约 14.69 秒。

SC 还有独立的采样差异：10/24 对新题的最终回答起始输入与选中思考完全一致，但回答调用种子不同，答案也不同。旧控制器按主调用次数派生种子，动态探测会改变该计数。SC 答案采用 32-token 分块，验证式 IS 的候选答案则一次生成最多 512 token，并返回已评分的缓存答案。共享题目种子不等于共享最终回答随机流。

另外两对验证式 IS（DEV_Q243、DEV_Q306，均为第二种子）在相同搜索输入下出现了不同答案。原始日志中首次分歧分别位于 `leaf_answer` 第 9 个调用和 `leaf_verify` 第 16 个调用（索引从 0 开始）；相应调用的输入、种子和长度上限相同，输出仍不同。两边均只执行一个完整搜索池，因此不能把这两处差异归因于搜索轮数。原因尚未定位，本轮不提供原生重复执行逐 token 确定性的保证。离线重算已保存日志的确定性是另一件事。

这些都是冻结运行的解释性诊断，没有据此更改提示词、种子或选择算法。逐对记录见 [context-comparisons.jsonl](context-comparisons.jsonl)。

## EOS、空回答与答案截断

| 检查项 | 结果 |
|---|---:|
| 最终选中答案为空 | 0/320 |
| 最终选中路径出现 thinking EOS | 0/320 |
| 最终选中路径插入后立即 close/EOS | 0/320 |
| 全部 thinking/search 调用中含 EOS | 1/3,437 |
| 证据搜索起点立即 close/EOS | 0/726 |
| 任意 search 调用首 token 为 close/EOS | 0/3,149 |
| 候选答案为空 | 0/792 |
| 候选答案触及长度上限 | 407/792 |
| 新题选中答案触及长度上限 | 169/192（88.0%） |
| 旧题选中答案触及长度上限 | 0/128 |
| 达到思考长度上限后强制闭合 | 新题 29/192；旧题 30/128 |

唯一的原始 thinking EOS 来自 `DEV_Q184:20261110:dynamic_legacy_sc` 的第 9 个调用：没有证据注入，在该调用生成第 192 个 token 时结束；它不是首 token EOS，也没有成为最终选中路径。故不能把它记作插入格式导致立即结束。

没有观察到插入后立即结束思考的现象，但这不能证明格式对整个思考分布没有影响。无关正文控制保留了来源标题、外壳和来源 ID，仅正文 token 数严格匹配；标题仍可能提供主题信息。无证据时真实/无关分支共用实际执行，不应当作两次独立试验。

答案截断是本轮的明显限制：新题中旧动态与两个无关正文组均为 24/24 截断，动态验证式 IS 为 21/24，静态验证式 IS 为 19/24。旧回归题保留了之前的“简洁回答”附加句，新题使用原始题面，没有这一附加句。同题所有方法的题面一致，但不能把跨组截断率或绝对 F1 的差异全部归因于难度或泛化。发现差异后仍保持本轮输入冻结。

原始异常定位见 [raw-stop-events.jsonl](raw-stop-events.jsonl)。强制思考闭合、自然 EOS、答案长度上限是三类不同事件。

## 检索与验证器的边界

78 次独立证据检查接受了 58 个包，其中 2 次提取器输出为无效 JSON。新题动态候选集合命中标注来源文档的比例为 50%，最终选中标注来源的比例为 33.3%；静态分别为 58.3% 和 41.7%。标注来源命中只是诊断：其他来源也可能提供正确证据。

792 次实际候选答案验证中，44 次未通过正分数的字面引用约束：38 次引用超过 16 个词，另 6 次长度合规但不是正文的精确连续引用；均按冻结规则计入惩罚。这不等于 44 次答案事实错误。另一方面，通过引用格式检查也不代表验证器正确判断了全部实质性断言。

固定复核了 8 道回归题与 3 道预先选定新题的第一种子，每题 5 个方法，共 55 份答案；哈希全部与完整原始日志相符。复核只解释样例，不给总体事实准确率：

- DEV_Q102、DEV_Q186 的短证据分别补上“散列成本可忽略”和“response file 需要完整路径”的核心事实；DEV_Q008 的 HSM `crypto-export` 核心规则也得到支持。
- DEV_Q160、DEV_Q209 虽检索到相关文档，短摘录仍漏掉必要列表或具体操作；相关来源不等于答案所需证据齐全。
- DEV_Q077 仍丢失 Gradpack 的特定许可情形；DEV_Q184、DEV_Q022 无证据时仍给出不符合历史参考答案的解释。验证器能够标记缺乏支持，却不会自动拒答。
- DEV_Q016 的回答方向部分正确，但漏掉关键方法签名、部署与注册信息，并补写了证据没有提供的细节。部分这类答案仍被验证器判为完整、无额外错误。

详细审阅见 [manual-case-notes.jsonl](manual-case-notes.jsonl) 和 [manual-review-audit.json](manual-review-audit.json)。这里比较的是历史基准答案，不提供当前产品操作或许可建议；没有执行模型生成的任何技术命令。

## 预先固定的按证据分流策略

在任何新题模型输出产生前，另行登记了“接受证据就用验证式 IS，否则用 SC”的规则；此时已经看到两道回归题的部分输出。它是原生条件的精确分流，不新增模型调用或独立试验。

新题动态分流 F1 为 13.714，静态分流为 14.820。动态分流相对动态验证式 IS 为 −0.355 [−0.865, 0.091]；静态分流相对静态 SC 为 +0.070 [−0.760, 1.048]。因此不把静态分流的最高均值宣传为稳定新收益。160 个派生视图的 466 项检查全部通过，登记时日志前缀哈希也吻合。详见 [ADAPTIVE.md](ADAPTIVE.md)。

## 预算、资源与可复现性

主模型启用 thinking，没有 `low` 提示；辅助提取与验证调用使用不输出思考的贪心 JSON。工作预算为 8,192，包含草稿、被丢弃前缀、候选生成、检索辅助调用及验证器。验证式 IS 把所有候选答案计入工作预算；SC 的一个最终答案单独记账。本批实际最大工作 token 为 7,439，最大总生成 token 为 7,951，**所有 320 条件实际总生成均不超过 8,192**。这仍不是等实际 FLOPs 的实验。注入的证据 token 属于输入，不计入生成预算，其前填和上下文成本计入执行图估算。

正式生成源码冻结于 `2a806da88d952fb266ec92f15609261fad1d8ca0`。198 上物理 0、1 卡各一个 TP1 副本、各 160 条件，同题的所有方法和种子都在同卡运行。两个生成程序均退出 0；容器在生成结束后由启动器停止，容器清理记录中的 137 不表示生成失败，OOM 标志均为 false。自己的两卡任务及此前尝试容器均已停止，资源登记已释放。未修改共享主工作树。

正式运行实际执行 418 个共享或独立单元，生成 1,204,493 token；执行单元耗时合计约 7.39 小时，图估算 327.715 PFLOPs。两副本并行的最长任务约 4.11 小时。这些是执行单元统计，不包含全部准备、预检和传输时间。B 机预检中的主机内存失败、三版原生预检和初始化失败记录均保留，未把失败尝试当作正式结果。

主审计 **59,561 项通过**；分流检查 **466 项通过**；人工复核 **55 份答案哈希通过**。离线交付回放另附 [OFFLINE-VERIFICATION.json](../OFFLINE-VERIFICATION.json)，区分离线重算已保存轨迹与重新运行模型。完整包包含每个候选、辅助调用、证据、计分、选择结果、冻结源码、运行时和权重哈希；模型权重本体不随包复制。

本轮没有重新加入此前较强的 SC-BoN，因此不能声称超过所有已测试 IS 变体。新旧 SC 控制还同时改变了 M/K/H（旧 M4/K2/H1024，新 M3/K2/H768），对旧动态的改善应归于整个检索与计算分配方案。12 道新题从排除既有文档组后的可回答集合选出，不能代表全部 TechQA。

## 下一轮优先修什么

本轮矩阵中，静态问题锚定短证据 + SC 的 F1 均值、生成 token 和耗时组合最实用；静态验证式 IS 则有更低的原生图估算计算量。动态方案仍应保留为实验分支，而不是因为超过旧动态就取代静态基线。

下一轮先统一简洁回答要求和最终回答采样方式、避免普遍的 512-token 截断，并复验 SC-BoN。检索侧优先保证关键步骤、参数和例外完整，采用能保留已证实步骤的小范围回退；验证侧需要逐断言检查，并把证据缺口转为再次检索或明确的不确定回答。以上是本轮完成后的后续方向，尚未在本轮新题上改动或重跑。
