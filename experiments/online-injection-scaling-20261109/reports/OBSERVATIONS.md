# 动态证据与 inference scaling 的组合试验

组合已实现并完成原生测试。新题上的 SC-BoN 有小幅正向信号，尚无稳定增益证据；动态检索组合仍未超过相同搜索方法下的静态 RAG。block-Metropolized IS K=2 在这轮技术问答上的收益更弱、实际开销更高。

固定 Qwen3.8-27B 权重，A 物理 NPU3、TP1；4 道按哈希选择且与历史文档组隔离的新题，另有 4 道按历史门控类型选出的回归题。3 种思考方式 × 5 种证据视图 × 8 题，共 120 个条件、119 个实际执行单元，一个 seed。新题和回归题分别统计。指标是对固定历史 gold 的归一化答案 token F1，不能作为事实正确率；全部条件的归一化 EM 均为 0。

| 思考方式 | 新题：静态 RAG | 新题：动态检索 | 回归：静态 RAG | 回归：动态检索 |
|---|---:|---:|---:|---:|
| 单路径长思考 | 10.712 | 10.089 | 24.015 | 17.108 |
| Self-Certainty BoN | 12.231 | 11.605 | 26.641 | 23.232 |
| block-Met IS K=2 | 10.906 | 10.345 | 22.429 | 20.192 |

单位为 F1 百分数，每格 4 题。新题中 SC-BoN 相对各自单路径：静态 +1.519 pp（配对 bootstrap 95% 区间 −1.464 至 +5.357），动态 +1.517 pp（−0.578 至 +2.824）。动态 SC-BoN 相对静态 SC-BoN 为 −0.626 pp（−5.519 至 +3.637）。block-Met 的新题增益分别只有 +0.194 / +0.256 pp，区间都跨 0。回归题中动态搜索有较明显改善，但这些案例按既知门控行为选择，不能充当泛化验证；其结果也仍低于静态 SC-BoN。

每个条件的搜索与辅助判断生成上限为 8192 token，最终答案另留 512；所有候选、rollout、JSON、EOS、废弃草稿均计费。注入证据属于输入，单包最多 256 token，额外分隔符和重建前缀的计算计入原生图估计。实际消耗不同：新题静态 SC-BoN 平均 3282 work token、66.78 秒、0.651 PFLOPs，单路径为 443、33.40 秒、0.322 PFLOPs；动态 SC-BoN 为 3704、88.07 秒、0.808 PFLOPs，动态单路径为 705、48.40 秒、0.415 PFLOPs。动态 block-Met 为 1.223 PFLOPs，约为动态单路径的 2.95 倍。

这轮匹配的是生成预算上限，没有匹配实际 FLOPs。SC-BoN 根据剩余容量一次预留完整候选，静态/闭卷最多 8 条、动态通常 7 条，每条后缀最多 1024 token；提前结束后不补满候选数。IS 为完整树预留最坏容量，不足以支付下一棵树时返回已有完整 rollout，因而可留有较多未用预算。本轮最大实际 work 为 7620。IS 的 40 个逻辑条件中，24 个只执行 1 轮、11 个执行 2 轮、5 个执行 3 轮。

实现采用阶段组合：先用最多 256 个主模型 token 做 FLARE/缺口探测，在保存的句段边界回滚未确认草稿，把短证据重建到原始 user 参考区，再搜索后续思考。每个搜索 epoch 固定上下文，证据变化时建立新 ledger 和候选池，SC 只评价新后缀。没有在候选树中多跳检索，没有跨上下文沿用权重，也不依赖原生 KV fork。此 BoN 是“思考后缀选优、最终答案生成一次”的适配，原论文完整输出选优的效果需另测。

共 5/8 题接受证据，新题为 3/4、回归为 2/4。两个历史接受检查点逐 token 复现旧实验，分别消耗 253/185 token。逐字引用检查仍有语义缺口：Q184 只得到重复调用的症状，未得到重复连线的原因；Q077 把普通授权用户规则套到 Gradpack 的许可异常；Q229 与 Q102 的规划分别错误猜测 Windows File Explorer 和 Cisco ISE，随后却接受了 IBM/Maximo 或 QRadar 的证据。Q229 的证据实际给出了正确 XML 属性，Q102 的证据部分回答了性能问题，但都没有支持规划中错误的产品实体。完整逐例判断见 `manual-gate-review.jsonl`。

全部 120 个条件均无空回答、无 thinking 内 EOS，也没有注入后首个选中 token 直接关闭 thinking。原始搜索与探测同样没有 EOS。出现 10 个逻辑条件的强制关闭，全部由所选后缀达到 1024 token 上限造成，对应 8 个独立执行单元；它们没有产生空回答。原始采样调用中有两次首 token 为 `</think>`，都位于 Q077 静态无关正文的一棵 IS 树中，前面已经生成 512 个思考 token，不能解释成注入后立即停止。当前使用 user 参考区重建格式，这些结果不替代上轮对 assistant-inline 格式的独立对照。

无关文本对照只替换正文，保留源标题、标签、包装及精确 token 长度；门控先在真实证据上执行。没有接受证据的 3 题，真实/无关视图共享同一次搜索结果。该对照衡量正文的增量作用，仍保留了标题中的主题线索。

51 项 CPU 检查通过；正式数据 13197 项审计通过，所有 119 个执行单元的思考与答案解码一致。全部 8 题、120 个条件和未选中候选都导出至 `traces/`，完整原生 ID、概率、SC、前缀、seed、停止原因在归档 JSONL 中。正式运行独立单元共生成 349027 个 work token，另有 24081 个答案 token，原生稠密填充图估计 84.797 PFLOPs；模型/索引加载、profiling 等初始化 FLOPs 未计入该估计，完整阶段耗时 8528 秒。静态证据离线准备不在逐条件计时中，动态在线检索在计时中。

当前更值得继续的是 SC-BoN 配合实体/版本一致性检查和更准确的证据窗口。应先阻止错误产品假设进入确认前缀、检查引用是否真正覆盖所缺事实，再扩大检索/搜索；本轮数据不支持单纯增加 IS 计算量就能稳定提升技术问答。

完整数值、逐题评分与配对区间见 `REPORT.md`、`summary.csv`、`graded.jsonl`；对照图见 `figures/retrieval-scaling.png`。方法依据为 [Self-Certainty Best-of-N](https://arxiv.org/abs/2502.18581v3) 和仓库既有 block-Met SC 变体；[compute allocation 研究](https://arxiv.org/abs/2408.03314v1) 提醒搜索收益依赖题目。这里保留负结果与实际成本，4 道新题、单 seed 的区间仅作描述。
