# 轨迹诊断与六种新在线方案的实际结果

256次正式测量已全部完成。静态事实注入仍以F1 **14.702**领先；六种新在线方案均未显示稳定优于原在线的收益：对原在线的六个问题级配对95%区间都包含0。结果是已查看16道DEV题上的探索，不是独立测试，也未校正多重比较。

## 上一轮为什么在线不如静态

原在线F1为12.520，静态为14.702；13/16题在线更低。三个空答案对整体差值贡献−0.990，占净差距45.4%。其余29个非空配对仍平均落后1.316，所以消除空答案本身不足以解释全部差距；这一分解也不能充当修复后的反事实结果。

| 原空答案 | 精确终止路径 | 本轮原在线是否复现 |
|---|---|---|
| Q292 / seed 20261112 | 第512个思考token后注入，再生成换行和EOS；没有发起答案请求 | 是 |
| Q244 / seed 20261113 | 第128个token后注入，紧接EOS；没有发起答案请求 | 是 |
| Q218 / seed 20261113 | 第128个token后注入，紧接思考结束标记；答案阶段仅换行和EOS | 是 |

这些路径没有耗尽预算，也没有截断。Q244已有相关命令，Q218已检索到匹配的APAR IT15252，说明获得相关资料之后，续写和答案读出仍会失败。原IS选择重放通过；SC会保留某些高分短路径，其统计不包含终止token，也不检查最终答案是否完整或正确。

非空失分有另外三类可见问题。Q183先猜Micro Focus或SolarWinds，导致错误检索或收到IBM资料后仍保留错误归属。Q025在线取到96–288窗口，漏掉静态192–377窗口内的keytool命令。原在线每条选中路径平均只收到384个证据token，静态固定512；在线答案也更长，词F1会受到冗长度影响。因而旧比较同时包含查询、窗口、时机、上下文角色和曝光量差异。

## 六种新方案改变了什么

**命令式继续推理提示获得最高在线点估计，但多数路径更早结束思考。** resume为13.633，比本轮原在线12.532高1.101，95%区间[−0.551, 2.725]；平均总生成量从3529降到1904，平均耗时从110.85秒降到71.75秒。然而24/32条选中路径在最后注入后不超过2个token就结束思考，原在线为11/32。低成本与更早结束思考同时出现，不能直接解释成更有效的长推理。旧Q244、Q292空答案消失，Q218仍空，并新增Q296/seed13空答案。

**第一人称未完成句续接最值得保留的是终止行为的变化。** bridge在本轮32次中空答案为0，注入后不超过2个token结束思考的路径也为0；旧三个空答案均产生了非空输出。F1为13.394，比原在线高0.862，区间[−1.475, 2.649]，尚无稳定质量提升证据。平均生成5135token、149.04秒，均约为静态的2.21倍。0/32只是本样本观察，不能视作已保证可靠性。

非空也不代表证据推理正确。例如Q218/seed13的bridge轨迹收到高度匹配的APAR，却续写“relevance ... is unclear, so I'm setting it aside”，最终答案又引用该APAR，并加入证据未明确支持的细节。Q292的bridge虽然不再为空，仍沿NetApp/存储故障方向作宽泛回答。

**句末优先策略修复了一些窗口问题，同时引入其他失败。** boundary将Q183两种子均值从12.60提高到23.97，Q025从12.07提高到21.57。Q025两个种子都取到192–377窗口，答案包含keytool命令；但seed13还把运行位置写成DataPower appliance，F1上涨不等同于所有细节正确。Q183/seed12的最终答案转而引用IBM指南，不过附加“仅适用于US”的断言也没有被该资料充分支持。

boundary在Q010、Q154、Q158各出现一个新空答案，整体F1降至12.378。其34次选中注入仅14次满足句末/换行规则，其余是截止点触发；它不是严格的完整句子注入。该策略还改变原生分段和派生随机流，不能把变化全部归因于语义边界。

**不确定性门控在当前流程中的影响很小。** adaptive只控制第二次注入。候选池中44次门控判断有29次不满足条件，但32个最终答案有31个与boundary逐字相同，仅Q271/seed13不同，平均F1只增加0.024。大量路径在早期注入后就结束，后期门控覆盖不到主要故障点。问题约束查询与去重组F1为13.405，相对resume差值−0.228，区间[−0.915, 0.517]，也未显示额外收益。

**把桥接提前到32/256没有解决总体问题，出现了长路径空答案。** early的F1为12.770，空答案3次，平均5561token、162.74秒。Q221/seed13只接受两次外部注入，却在选中模型输出中自行生成12次引用标题，反复复述相关但不完全匹配的Cloud/Web Start资料。选中思考达到5360token，全部候选与rollout消耗46887token，耗时1009.68秒，最后自然EOS，答案仍为空。Q244/seed13在第二次注入后6token结束为EOS；Q218/seed13在第二次注入后25token结束思考，答案阶段仍为空。这三次都不在“注入后≤2token结束”的统计里。

bridge同样存在格式复述风险：Q048/seed12的选中输出自行生成3次引用标题，全部生成33661token、耗时863.86秒。上述标题数已直接在排除外部插入的逻辑生成token中核验，不能解释为检索器真的调用了这么多次。

## 可以据此得出的判断

当前更明确的问题是证据拼接后的终止行为、错误假设是否被纠正，以及引用格式被模型自行续写；增加查询融合或在后期加门控未触及所有这些问题。第一人称续接提供了值得进一步隔离测试的格式方向，但在这个版本里，成本增加和引用复述仍然明显。现有证据支持继续使用静态注入作为基线，尚不支持将任何新在线方案视作优胜者。

后续若继续研究，应在未查看题目上冻结测试，并分别控制证据窗口、输入长度和采样分段，以区分格式、时机和检索的贡献。原IS及SC按用户要求保持不变；若将来要改变选择目标，需要另作清楚标注的实验。

## 完整性与复现

正式256次原生运行的91,362项审计通过，48次TRAIN验证的12,705项审计通过；此前36次TRAIN格式试验和首次启动失败记录也保留。52项本地测试及原17个IS文件的冻结校验见local-validation.json。总生成764,794token，累计测量6.919小时，设备占用7.143小时；三张卡的本次容器均已停止。16次空答案均计分；无答案截断或选中思考的强制结束。

静态与原在线合计64次基线复测，63个最终答案与上一轮逐字相同。唯一差异为原在线Q271/seed12：F1从7.968变为8.369，使在线均值由12.520变为12.532；保留这次新输出，不挑选或重跑。不能把本轮基线宣称为逐token完全复现。

离线审计、指标、图表、旧轨迹诊断和TRAIN格式对照已重放并逐字节一致。归档过程中修复了分析脚本默认文本编码和汇总JSON的CRLF/LF问题，未修改或补跑任何模型输出。机器生成报告与图表可通过replay.py复现；本讨论及案例摘录是对已归档数据的补充解读。
