## App Connect Professional (Cast Iron) Studio – Silent Launch / Crash

### Most Likely Root Cause: Incompatible JRE Version

Based on the available reference data, the primary cause of Studio failing to launch (or crashing shortly after appearing) on Windows is a **Java version mismatch**. Specifically:

- The machine has **Java 1.7 JRE** (or a newer JRE) installed and configured as the system default.
- The Cast Iron / App Connect Studio launcher attempts to use that JRE via **Java Web Start**.
- The supported runtime for the v6.x Studio Web Start launcher is **Java 1.6 JRE**. Java 1.7 is **not supported** and causes the launcher to fail.

The underlying exception, when it does surface, is:

```
com.sun.deploy.net.FailedDownloadException: Unable to load resource:
https://cloud2.castiron.com/flash/design/com.approuter.studio.launcher-1.0.0.jar
```

When the failure is silent (no dialog, no log window), the launcher process simply exits after the JRE incompatibility is detected, which matches the "appears for a few seconds then vanishes" symptom you described.

### Remediation Steps

1. **Install / verify Java 1.6 JRE** (the version the Studio Web Start launcher expects) on the Windows machine.
2. **Remove or disable the Java 1.7 (or newer) JRE** so the launcher cannot pick it up:
   - Uninstall the 1.7+ JRE via *Control Panel → Programs and Features*, **or**
   - If a newer JRE must remain for other applications, remove it from the `PATH` and set the `JAVA_HOME` environment variable to point to the 1.6 JRE.
3. **Clear the Java Web Start cache** (File → Delete Temporary Files, or delete the contents of `%USERPROFILE%\AppData\LocalLow\Sun\Java\Deployment\cache`) so the launcher re-fetches the correct JAR bundle.
4. **Relaunch Studio** from a clean command prompt and, if it still fails, run from `javaws -verbose <url>` to capture the full stack trace for confirmation.

### Additional Checks (if the JRE fix does not resolve the silent crash)

- Ensure the `com.approuter.studio.launcher-1.0.0.jar` can be downloaded (check firewall / proxy for blocks on `*castiron.com`).
- Verify the Windows user account has write access to the `%TEMP%` and Java deployment cache directories.
- Confirm no javapath or `java.exe` from an unattended JRE is shadowing the correct one in `PATH`.

**Key takeaway:** The silent crash is almost always a JRE version incompatibility (1.7 used where 1.6 is required). Aligning the Java runtime to the supported version and clearing the Web Start cache resolves the issue.

# App Connect Professional (Cast Iron) Studio – Silent Crash on Launch

## Diagnose First

The single most important step is to capture the crash log before attempting any fix:

1. **Locate `error.log`** in the Studio installation directory (e.g., `C:\Program Files\IBM\CMS1\<version>\error.log` or the equivalent path on Linux/macOS).
2. Look for the last entries – they will typically show a **Java `OutOfMemoryError`**, a **`UnsatisfiedLinkError`**, or a **missing/incompatible `java.dll` / `libjvm.so`** reference, which pinpoints the real root cause.

## Common Root Causes and Fixes

### 1. Java Runtime Mismatch or Corruption
- Studio bundles (or requires) a specific JDK version. If the system `JAVA_HOME` points to a different or corrupted JDK, the bundled launcher may crash silently.
- **Fix:** Open the `App Connect Studio.ini` (or `Studio.ini`) file in the install directory and verify/force the `-vm` argument to point at the correct, bundled JDK:
  ```
  -vm
  C:\Program Files\IBM\CMS1\9.0\jre\bin\javaw.exe
  ```
  Remove any conflicting `-vm` or `JAVA_HOME` override, and reinstall the bundled JRE if `error.log` shows a missing JVM component.

### 2. Corrupted Eclipse Workspace
- A damaged `.metadata` folder inside the workspace causes the underlying Eclipse platform to abort before the UI renders.
- **Fix:** Rename or delete the `\<workspace>\.metadata` folder (back it up first). Studio will recreate it on next launch. Do **not** delete project source files.

### 3. Insufficient Memory / VM Arguments
- The default heap may be too low for the machine, causing an ungraceable `OutOfMemoryError` at class-loading time.
- **Fix:** Edit `Studio.ini` and raise the heap:
  ```
  -Xms512m
  -Xmx2048m
  ```
  If you have 16 GB+ RAM, `-Xmx` can be set to 4096m.

### 4. Corrupted or Incompatible Installation
- Antivirus, Windows Update, or an interrupted install can corrupt native libraries (`eclipse_*.dll`, `swt_*.dll`).
- **Fix:**
  - Temporarily disable antivirus/EDR and retry.
  - Run the Studio installer as **Administrator** in Windows.
  - If still failing, **fully uninstall** (including leftover folders under `C:\Program Files\IBM\CMS1` and `C:\Users\<user>\.AppConnect*`), then do a clean install.

### 5. Operating-System / Desktop-Environment Incompatibility (Linux)
- On RHEL/CentOS, a missing `libXtst.so`, `libcanberra-gtk-module.so`, or a Wayland session instead of X11 can cause an immediate silent exit.
- **Fix:** Install the required `gtk2`, `xtst`, and `canberra` packages; log into an **X11** (not Wayland) session; and launch from a terminal to capture stderr:
  ```bash
  cd <install_dir>/CMS1
  ./AppConnectStudio 2>&1 | tee /tmp/studio_stderr.log
  ```
  The terminal output will reveal the failing shared library.

### 6. File-Path or Permission Issues
- Install path containing spaces, non-ASCII characters, or group/other-write permissions on the install directory can break the native launcher.
- **Fix:** Reinstall to a path like `C:\IBM\CMS1` or `/opt/ibm/cms1` with **owner-only write** permissions.

| 4 | Increase `-Xmx` in `Studio.ini` |
| 5 | Rename `\<workspace>\.metadata` |
| 6 | Disable AV/EDR; ensure install path is clean |
| 7 | Clean reinstall of Studio (and, if needed, a patch/fix from IBM APAR/PTF) |

com.sun.deploy.net.FailedDownloadException: Unable to load resource:
https://cloud2.castiron.com/flash/design/com.approuter.studio.launcher-1.0.0.jar

# App Connect Professional (Cast Iron) Studio Crashes on Launch

## Most Common Cause: Java/JVM Mismatch

The silent crash (window appears, then disappears with no error dialog) is almost always caused by a **Java runtime incompatibility**. Studio ships with or expects a specific JDK version. If your system's `JAVA_HOME` or `PATH` points to a newer or incompatible JDK, the Studio launcher fails silently.

### Fix – Correct the Java Version

1. Open the Studio launcher configuration:
   - **Windows:** `%APPDATA%\App Connect Professional\studio.ini` (or the `eclipse.ini` inside the install directory).
   - **macOS/Linux:** `<install_dir>/configuration/configuration.ini` or `studio.ini`.

2. Locate (or add) the line:
   ```
   -Djava.home=C:\path\to\bundled\jdk
   ```
   Point it to the **JDK bundled with Studio**, not a system-wide Java. On a default Windows install this is typically:
   ```
   <install_dir>\jre\bin    (or \jdk\)
   ```

3. Alternatively, remove any `-vm` or `-Djava.home` overrides so the launcher uses its own embedded JRE.

4. If you recently installed or updated Java on the OS, **uninstall the newer JDK** or adjust `JAVA_HOME`/`PATH` so the system Java no longer shadows the bundled one.

## Other Diagnostics if the Issue Persists

| Step | Detail |
|------|--------|
