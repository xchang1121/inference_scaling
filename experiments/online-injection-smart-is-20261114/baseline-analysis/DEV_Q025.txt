## Importing a Certificate for the ITCAM Agent for Data Power (BN Agent)

When the ITCAM Agent for Data Power is missing a required certification, the trace log will show an error such as:

```
javax.net.ssl.SSLHandshakeException: Received fatal alert: handshake_failure
```

To resolve this, import the certificate file into the agent's Java keystore using the `keytool` command.

### Prerequisites

- The certificate file must be in **ASCII** format (not binary).
- You can use either a **`.cer`** or **`.pem`** file.
- You need the path to the JRE used by the agent (e.g., `/usr/ITM/JRE/aix526/jre/`).

### Command

Run the following `keytool` command:

```bash
/usr/ITM/JRE/aix526/jre/bin/keytool -import -trustcacerts \
  -alias <alias_name> \
  -keystore /usr/ITM/JRE/aix526/jre/bin/lib/security/cacerts \
  -storepass <storepass> \
  -file /path/to/certificate.cer
```

### Example

```bash
/usr/ITM/JRE/aix526/jre/bin/keytool -import -trustcacerts -alias ligitalsso \
  -keystore /usr/ITM/JRE/aix526/jre/bin/lib/security/cacerts \
  -storepass c<storepass> \
  -file /NEWSSL-sscert.cer
```

### Key Points

| Parameter | Purpose |
|-----------|---------|
| `-import -trustcacerts` | Imports the certificate as a trusted CA entry |
| `-alias <name>` | Arbitrary alias to identify the certificate in the keystore |
| `-keystore <path>` | Path to the `cacerts` file in the JRE's `lib/security` directory |
| `-storepass <pass>` | Password protecting the keystore |
| `-file <file>` | Path to your `.cer` or `.pem` certificate file |

After importing, restart the ITCAM Data Power agent so it picks up the new trusted certificate. The `SSLHandshakeException: handshake_failure` error should no longer appear in the trace log.

# Importing a Certificate in ITCAM for Data Power

## Prerequisites

- You need the server/certificate file (in **`.cer`** or **`.pem`** format).
- The file **must be in ASCII (text) format**, not binary. If it is binary, convert it before importing.
- Ensure you have administrative access to the ITCAM for Data Power agent host.

## Step-by-Step Procedure

### 1. Identify the Keystore Location
The ITCAM agent for Data Power (BN Agent) uses a keystore managed by the bundled JRE, typically located under:

```
/usr/ITM/JRE/      (or your actual Java installation path on the agent host)
```

The default keystore is usually `cacerts` (or a custom keystore specified in the agent configuration).

### 2. Run the `keytool` Import Command

From the agent host, execute the following command:

```bash
/usr/ITM/JRE/bin/keytool \
  -import \
  -trustcacerts \
  -keystore /usr/ITM/JRE/lib/security/cacerts \
  -storepass changeit \
  -alias dp_cert_alias \
  -file /path/to/your/cert_file.cer
```

| Parameter | Description |
|-----------|-------------|
| `-import` | Import a trust certificate into the keystore |
| `-trustcacerts` | Also examine and update trusted CA certificates |
| `-keystore` | Full path to the Java keystore file |
| `-storepass` | Keystore password (default is `changeit`) |
| `-alias` | A unique name/label for the certificate |
| `-file` | Path to the certificate file (`.cer` or `.pem`) |

### 3. Confirm and Restart
- When prompted, type **`yes`** to confirm the fingerprint.
- Restart the ITCAM for Data Power agent service:

```bash
# Example (Linux)
/etc/init.d/ITMagent restart
# or
/usr/sbin/itmadm stop agent && /usr/sbin/itmadm start agent
```

### 4. Verify the Import
- Check the agent trace/log for SSL handshake errors. A previously missing or untrusted certificate will produce errors such as:

  ```
  ERROR – BODAPPS57 – javax.net.ssl.SSLHandshakeException: 
  Received fatal alert: handshake_failure
  ```

- After a successful import and restart, the Data Power appliance should appear as **online/managed** in the ITCAM for Data Power GUI.

## Important Notes

- **ASCII vs. Binary**: If your `.cer` file is in DER (binary) format, convert it to PEM/ASCII first:
  ```bash
  openssl x509 -inform der -in cert.der -out cert.pem
  ```
- **File permissions**: Ensure the ITCAM agent process (usually running as the `ITMUser` or `omonitor` user) has read access to the certificate file and the keystore.
- **CA chain**: If the server certificate is signed by an intermediate CA, import the full chain (root CA → intermediate CA → server cert) in order.
- **Multiple appliances**: Repeat the import for each Data Power sub-node/hostname managed through the agent if each uses a different certificate.

This process resolves `handshake_failure` and `SSLHandshakeException` errors that occur when the ITCAM for Data Power agent cannot validate the Data Power appliance's TLS certificate.

# Importing a Certificate in ITCAM for Data Power

The ITCAM for Data Power (BN Agent) requires a certificate for secure (SSL/TLS) communication with the TDI/TCAM controller. Below are the steps to import it.

## 1. Prepare the Certificate File

- Convert the certificate to **PEM** or **PKCS#12 (PFX)** format.
- Ensure the file is in **ASCII** encoding (not binary). A `.pem` file should contain the full chain (or at minimum the leaf cert) and, if a private key is needed for mutual TLS, the key as well.

## 2. Import the Certificate

### Option A – Via the Java Keytool (agent keystore)

The BN Agent uses a Java keystore. From the operating system shell on the host where the agent runs (and where JRE is installed):

```bash
# For a standalone CA / public certificate (trust-only)
keytool -import \
  -alias itcam_dp \
  -file <your_cert_file>.crt \
  -keystore /usr/ITM/JRE/lib/security/cacerts \
  -storepass changeit \
  -noprompt

# For a full PFX bundle (cert + private key, mutual TLS)
keytool -importkeystore \
  -destkeystore <agent_keystore>.jks \
  -deststorepass <store_pass> \
  -srckeystore <your_bundle>.pfx \
  -srcstoretype PKCS12 \
  -srcstorepass <pfx_pass>
```

Replace `/usr/ITM/JRE` with your actual Java installation path and `<your_cert_file>` with the real file name.

### Option B – Via the Data Power Administration UI

If the certificate belongs to the Data Power system store (needed for the gateway's own listener or for the agent to present as a client certificate):

1. Log in to the **Data Power Web GUI** (or connect via SSH/CLI).
2. Navigate to **Config → System → Certificates**.
3. Click **Import**.
4. Upload the `.pem` or `.p12`/`.pfx` file, set an alias, and confirm the import.
5. Verify the new entry appears in the certificate list.

## 3. Reference the Certificate in the ITCAM Agent Configuration

In the agent profile (typically an XML or properties file under the agent install directory, e.g., `…/ITCAM/agent/config/`):

```xml
<ssl-config>
  <keystore path="/path/to/agent_keystore.jks"
            password="&lt;store_pass&gt;"/>
  <key-alias itcam_dp/>
  <trust-store path="/usr/ITM/JRE/lib/security/cacerts"
               password="changeit"/>
  <enabled>true</enabled>
</ssl-config>
```

Adjust the paths, passwords, and alias to match what you used during import.

## 4. Restart the ITCAM for Data Power Agent

```bash
# Typical service command (adjust for your environment)
cd /usr/ITCAM/bin
./stopagent.sh   # or: stop_bn_agent.sh
./startagent.sh  # or: start_bn_agent.sh
```

## 5. Verify

- Check the agent trace log for the previous `SSLHandshakeException / handshake_failure` error. It should no longer appear.
- Confirm the agent is communicating with TDI:
  ```bash
  # Look in the trace for successful SSL handshakes
  grep -i "ssl\|handshake" <trace_file>
  ```
- Optionally, run `openssl s_client -connect <tdi_host>:<port>` from the agent host to confirm the certificate chain is being presented correctly.

## Troubleshooting Tips

| Symptom | Likely Cause |
|---|---|
| `handshake_failure` in trace | Wrong or missing CA cert in truststore |
| `certificate_unknown` | Agent's client cert not signed by a CA the TDI trusts |
| `file not found` error on import | Certificate file is binary; re-encode to ASCII/PEM |
| Keytool "Password must be at least 6 characters" | Change the keystore password before importing |

> **Note:** The exact keystore path and configuration file names vary by ITCAM level (e.g., 7.3 vs. 8.1) and by whether the agent is deployed as a standalone process or embedded in a WebSphere Administrative Console. Consult the *ITCAM Agent for Data Power Installation and Configuration Guide* for your specific release for precise paths.
