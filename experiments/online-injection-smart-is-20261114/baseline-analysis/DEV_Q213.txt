## Short Answer

**No.** There is no automated migration or conversion path that turns Workplace XT search templates into ICN (IBM Content Navigator) native **managed search templates**. The two template systems use different internal definitions, and IBM does not provide a tool or utility to convert one to the other.

### What *is* supported in ICN

- **Visibility & execution:** XT-created search templates (and XT-created stored searches) are still visible in ICN. You can **run** them, but you **cannot edit** them in ICN.
- **Restriction:** Stored searches or templates that return a mixed result set of both documents *and* folders are not supported in ICN.
- **ICN-native objects:** ICN can create and fully manage its own native managed search templates, but it cannot *author* XT-style stored searches.

### Practical migration approach

Because a direct conversion is not possible, the standard workaround is:

1. **Inventory** every XT search template in the relevant namespace(s) (they are stored at the namespace level in the object store).
2. **Note the criteria** – each XT template is essentially a set of property/value filter predicates, a sort order, and an output column list.
3. **Recreate each template in ICN** as a native managed search template:
   - In ICN, go to **Search → Manage Search Templates** (namespace admin) to create a new template.
   - Re-enter the same filter criteria, field selections, and sort order.
   - Publish the new ICN template to the intended user groups or roles.
4. **Retire** the old XT templates once all users have confirmed the ICN equivalents work correctly.
5. **Stored searches** (user-level saved searches) follow the same logic: they remain readable/runnable in ICN but must be rebuilt as ICN "saved searches" if the user needs to modify them.

### Key limitation to plan around

Because the recreation is **manual** (or semi-automated at best by exporting the XSDB/relational definitions and rebuilding the UI), any large estate of templates should be treated as a project with user validation, not a "click-migrate" step in the overall XT-to-ICN switchover.

**Bottom line:** You can *see and run* XT search templates from ICN, but you cannot *convert* them into ICN managed search templates. They must be rebuilt natively in ICN.
