## Clearing Errors in `crm_mon`

To clear a failed resource action displayed in `crm_mon`, use the **`crm_resource`** command with the `-C` (clear) flag:

```bash
crm_resource -r <resource_name> -H <hostname> -C
```

### Parameters

| Flag | Meaning |
|------|---------|
| `-r` | Name of the failed resource (as shown in the `crm_mon` output) |
| `-H` | Host/node name where the failure was recorded |
| `-C` | Clears the failed action record for that resource on that host |

### Example

If `crm_mon` shows a failed action like:

```
drbd_exphome_device_start_0 (node=netezza_h2, call=15, rc=1): Error
```

You would run:

```bash
crm_resource -r drbd_exphome_device -H netezza_h2 -C
```

After executing the command, the error entry for that resource on that host will be removed from the `crm_mon` display. If multiple resources have failed actions, repeat the command once per resource/host combination.

# Clearing Errors Found in `crm_mon`

`crm_mon` (part of the **Pacemaker** cluster resource manager) displays recorded failures, fail counts, and pending/stuck operations. These errors must be cleared before the cluster will retry or re-failover a resource.

## 1. Identify the Error

Run a one-shot, fully-verbose view:

```bash
sudo crm_mon -A1 -r -f
```

Look for lines such as:

```
* State: Last-failure 'Tue Jun  4 10:22:31 2024' (rc=refresh)
   ... 3 errors
```

Note the **resource name**, the **node**, and the **operation** (e.g., `monitor`, `start`, `stop`).

## 2. Clearing Fail Counts (most common fix)

| Command | What it does |
|---|---|
| `sudo crm_resource -F -r <resource>` | Resets the fail count for the resource on **all** nodes |
| `sudo crmadmin --clear-failcount <resource> <node>` | Clears the fail count on **one specific node** |
| `sudo crm resource failure --reset <node> <resource> <op>` | Removes a **single failure record** (operation = `monitor`, `start`, `stop`, etc.) |

Example:

```bash
sudo crm_resource -F -r myapp
# or, for a specific node
sudo crmadmin --clear-failcount myapp node2
```

## 3. Cleaning Up Stuck / Pending Operations

If an operation is stuck in `Pending` or `Running` state (common after a node crash), reset the resource's operation history:

```bash
sudo crm resource cleanup -r <resource>
```

For a specific node:

```bash
sudo crm resource cleanup -i <node> -r <resource>
```

> `--cleanup` performs a **`crm_resource --reset`** under the hood: it deletes pending operations, clears fail counts, and re-submits any uncompleted actions.

## 4. Resetting a Resource Entirely

If the resource is in a bad state after multiple failures:

```bash
sudo crm_resource --reset -r <resource>
```

This is equivalent to:

```bash
sudo crm_resource -F -r <resource>
sudo crm resource cleanup -r <resource>
sudo crm_resource --wait -r <resource>
```

## 5. Verifying the Clearance

After running the commands, confirm the errors are gone:

```bash
sudo crm_mon -A1 -r
```

The resource should show no error count, no `Last-failure` line, and no pending operations.

## Important Cautions

- **Fix the root cause first.** Clearing fail counts (e.g., with `crm_resource -F`) without resolving the underlying problem (bad config, disk full, network partition, stale IP) will cause the resource to fail again immediately.
- If a resource is in **`Stopped`** or **`Failed`** and the cluster has set a restriction (e.g., `migration-threshold` reached), you may also need to reset the migration throttle:

  ```bash
  sudo crm resource clear-restrictions -r <resource>
  # or
  sudo crm_resource -U -r <resource>
  ```

- After clearing, force a re-evaluation:

  ```bash
  sudo crmadmin --validate-cib -x /etc/corosync/crm/cluster.xml   # if using file-based CIB
  sudo crm resource failcount-show
  ```

## Quick Reference

```text
sudo crm_resource -F -r RES            # clear all fail counts
sudo crm resource cleanup -r RES       # reset ops + fail counts
sudo crm resource failure --reset NODE RES OP
sudo crm_resource --reset -r RES       # full reset
sudo crm_mon -A1 -r                    # verify
```

Apply the fix, clear the errors in the order above (root cause → cleanup → fail-count reset → verify), and the `crm_mon` output should return to a clean state.
