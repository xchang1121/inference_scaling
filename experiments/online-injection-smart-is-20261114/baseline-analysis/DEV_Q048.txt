# ITM IIS Agent – Required Performance Counters

## Overview

The Tivoli Monitoring (ITM) IIS agent collects data from **Microsoft IIS** via Windows Performance Counters. The specific counters needed depend on which **attribute sets** you have enabled for monitoring. The primary categories are **Website Details**, **Website Status**, and (optionally) **Worker Process** data.

---

## 1. Website Details (per-site instance data)

These counters are pulled from the **`\W3SVC(*)`** and **`\IIS Web Server(*)`** categories (instance = site ID / name):

| Counter | Category | Purpose |
|---|---|---|
| `Bytes Received/sec` | W3SVC / IIS Web Server | Inbound traffic |
| `Bytes Sent/sec` | W3SVC / IIS Web Server | Outbound traffic |
| `Anon Connections/sec` | W3SVC / IIS Web Server | Anonymous request rate |
| `Auth Failures/sec` | W3SVC / IIS Web Server | Failed auth rate |
| `Total Bytes In/Out` | W3SVC(*) | Cumulative bytes |
| `Requests/Sec` | W3SVC / IIS Web Server | Request throughput |
| `Total Request Queues` | IIS Web Server | Backlog size |
| `Current Connections` | W3SVC / IIS Web Server | Active connections |
| `Total Not Found Errors` | W3SVC(*) | 404 count |
| `Total Bad Request Errors` | W3SVC(*) | 400 count |
| `Total Server Errors` | W3SVC(*) | 5xx count |
| `Bytes Total In/Out` | W3SVC(*) | Lifetime totals |

## 2. Website / Server Status (global + per-site)

Pulled from **`\IIS Web Server`** (global instance) and **`\W3SVC`** with the special instance name:

| Counter / Data | Category | Purpose |
|---|---|---|
| `Server Quote` | IIS Web Server | Server-side quote |
| `Total HMC Counters` | IIS Web Server | Health counters |
| `Current Anonymous Connections` | IIS Web Server | Global anon count |
| `Total Anonymous Connections` | IIS Web Server | Lifetime anon |
| `Current Authenticated Connections` | IIS Web Server | Global auth count |
| `Bytes Accepted/sec` | IIS Web Server | Accepted bytes rate |
| `Bytes Rejected/sec` | IIS Web Server | Rejected bytes rate |
| `Requests Queued` | IIS Web Server | Queued requests |
| `Total Bytes Accepted` | W3SVC | Lifetime accepted |

For **IIS 7/7.5/8**, the object names shift to **`\W3SVC_W3WP`**, **`\W3SVC`**, and **`\ASP.NET\Requests`** in addition to the above.

## 3. Worker Process (optional, if enabled)

| Counter | Category |
|---|---|
| `% Processor Time` | Process(w3wp) |
| `Working Set` | Process(w3wp) |
| `Request Execution Time` | ASP.NET App Worker Process |
| `Requests Queued` | ASP.NET App Worker Process |
| `Request Queue Length` | ASP.NET / W3SVC_W3WP |

## 4. How to Confirm What Your Agent Is Actually Reading

The exact counter list encoded in the ITM agent is defined in the agent's **PE component** (`.pe` resource file) on the **Tivoli Enterprise Monitoring Server (TEMS)**. To audit it:

1. On the TEMS, open a text editor (or `strings` on Linux) on the IIS agent PE file (e.g., `aegis.pe`, `iis.pe`, or whatever name is listed under **NETOPSA > Agent Components** in TEMS Console).
2. Look for `PerfCounter` / `PerfCategory` sections – they list each counter name, category, and instance mask the agent queries.
3. Alternatively, run **Performance Monitor (perfmon)** on the **managed** Windows host, add the following objects, and compare with the ITM attributes arriving in the **Attribute Explorer** on the TEMS:
   - `W3SVC(*)`
   - `IIS Web Server(*)`
   - `ASP.NET(*)` (IIS 7+)
   - `W3SVC_W3WP(*)` (IIS 7.5+)

## 5. Documentation Note

The IBM knowledge-center articles that explain the IIS agent in detail are **ISV-series** documents (e.g., *Tivoli Monitoring: Implementing – Agent Powerplay: IIS*). They list the attribute names (e.g., `W3SVC_CurrentConnections`, `IIS_BytesReceivedPerSec`) but do **not** always tabulate the raw Windows counter names. The PE file on the TEMS is the single source of truth for the exact counter strings the agent opens through the `PDH_*` Win32 API.

5. Check **Agent Manager → Collectors → IIS** on the agent for `STATUS_OK` / counter-binding errors in the log.

# IIS Performance Counters Required for the ITM IIS Agent

The IIS documentation does not present the counter list in a single "required-for-monitoring" table, which is why it's hard to locate. Below is the explicit set of Windows performance counters the ITM IIS agent consumes to report **website details** and **web-site status**.

## 1. Per-Instance / Total – `W3SVC` object

This is the primary counter object. The agent reads it both for `_total` and for each named website instance (e.g., `W3SVC(website_name)`).

| Counter | Purpose |
|---|---|
| **Bytes Sent/sec** | Outbound bandwidth per site |
| **Bytes Received/sec** | Inbound bandwidth per site |
| **Total Hits/sec** | Overall request rate |
| **File Hits/sec** | Static-file request rate |
| **Get Hits/sec** | GET request rate |
| **Put Hits/sec** | PUT request rate |
| **Post Hits/sec** | POST request rate |
| **Head Hits/sec** | HEAD request rate |
| **Isapi Extension Requests/sec** | ISAPI/ASP request rate |
| **Current Connections** | Active client connections (status) |
| **Total Connection Receive Errors** | TCP receive errors (status) |
| **Total Data Sent Errors** | TCP send errors (status) |
| **Total Data Receive Errors** | TCP receive errors (status) |
| **Total Isapi Extension Receive Errors** | ISAPI receive errors |
| **Total Isapi Extension Send Errors** | ISAPI send errors |

> **Important (from IBM/CA APAR IZ17024):** If the `W3SVC` counters are in a *failed* state on the host, the agent historically introduced a memory leak because it tried to re-create the "Default Web Site" instance every poll cycle. The fix (pack-level) makes the agent skip counters in a "failed" state and log them as excluded. If you see memory growth on the agent, confirm the W3SVC registry key is intact:
> `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Perflib`
> and re-register with `lodctr /R` if needed.

## 2. `IIS Web Server` object (server-wide)

| Counter | Purpose |
|---|---|
| **Total Bytes Sent/sec** | Aggregate outbound bandwidth |
| **Total Bytes Received/sec** | Aggregate inbound bandwidth |
| **Current Connections** | Server-wide active connections |

## 3. `WWW Service` object (service-level status)

| Counter | Purpose |
|---|---|
| **Total Bytes Sent/sec** | W3SVC process-level TX |
| **Total Bytes Received/sec** | W3SVC process-level RX |
| **Current Connections** | Service-level connection count |

## 4. Process-level (supplementary, often included)

The agent may also poll the **Process(w3wp)** and **Process(IISADMIN)** objects for:

- **% Processor Time**
- **Working Set (Private)**
- **Thread Count**
- **Handle Count**

These feed the "process health" portion of the website-status view.

## Quick Reference – How to Verify on the Target Host

```powershell
# List all W3SVC counters and instances
Get-Counter -Counter '\W3SVC(_Total)\*' | Select-Object Counter, CookedValue

# Confirm no "failed" counter instances
Get-Counter -Counter '\W3SVC(*)\Current Connections' |
  Where-Object { $_.CookedValue -eq [double]::NaN }
```

If any counter returns `NaN` or is missing, the ITM IIS agent will exclude that datapoint (post-fix) or, in older agent versions, risk the leak described above.

## Summary

The **minimum** set the ITM IIS agent needs for its two report categories is:

| Report Category | Counters |
|---|---|
| **Website Details** (traffic, request mix) | `W3SVC`: Bytes Sent/sec, Bytes Received/sec, Total/ File/ Get/ Put/ Post/ Head Hits/sec, Isapi Extension Requests/sec |
| **Web Site Status** (health, connectivity) | `W3SVC`: Current Connections, Total Connection Receive Errors, Total Data Sent Errors, Total Data Receive Errors; plus `IIS Web Server` and `WWW Service` equivalents for service-level health |

All counters are standard Windows Performance Monitor objects exposed through PDH; no custom or IIS-specific SDK counters are required beyond what `lodctr` registers for W3SVC / IIS Web Server / WWW Service.
